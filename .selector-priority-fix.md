## 任务：修复搜索框选择器优先级

### 问题

`probeSearchInput` 中 `document.querySelectorAll(searchSelector)` 返回的是 DOM 顺序，
不是选择器书写顺序。如果 `input[placeholder*="搜索"]` 在 DOM 中排在 `#search-input-in-feeds` 前面，
会优先选中兜底输入框，而不是稳定 ID 的输入框。

### 改动

#### 1. ui_selectors.go

加上主选择器（稳定 ID）常量，保持现有 `SelectorSearchInput` 不变：

```go
SelectorSearchInputInFeeds        = `#search-input-in-feeds`
SelectorSearchInputInSearchResult = `#search-input`
SelectorSearchInput               = SelectorSearchInputInFeeds + `, ` + SelectorSearchInputInSearchResult + `, input[placeholder*="搜索"]` // 兜底：匹配 placeholder 含"搜索"的输入框
SelectorMarkedSearchInput         = `[data-xhs-mcp-search-input="1"]`
```

#### 2. search.go — probeSearchInput 的 JS

修改 JS 逻辑，先查 ID 选择器，查不到再查 placeholder 兜底，传入两个选择器：

```javascript
(searchSelector, primarySelector) => {
    // ...
    // 优先查稳定 ID
    let searchInput = Array.from(document.querySelectorAll(primarySelector)).find((el) => visible(el) && clickHit(el));
    // 没找到再查 placeholder 兜底
    if (!searchInput) {
        searchInput = Array.from(document.querySelectorAll(searchSelector)).find((el) => visible(el) && clickHit(el));
    }
    // ...
}
```

其中 `primarySelector` 是 `#search-input-in-feeds, #search-input`，
`searchSelector` 是完整版本（含 placeholder 兜底）。

#### 3. search.go — probeSearchInput 的 Go 调用

`probeSearchInput` 函数签名增加 `primarySelector` 参数：
```go
func probeSearchInput(page *hrod.Page, searchSelector, primarySelector string) (searchInputProbe, error) {
```

调用侧 `probeSearchInput(page, searchSelector, SelectorSearchInputInFeeds+`, `+SelectorSearchInputInSearchResult)`。

### 约束
- 不改动 ready.go
- 不改动 hrod 层
- 只改 ui_selectors.go 和 search.go 的 probeSearchInput 相关部分
